## 2. ❌ 需要新建

### 2.A 靶点库数据 ← **唯一需要外部获取的一项**

#### 现状

| 项 | 现状 |
|---|---|
| 前端 | `Targets.vue` 使用硬编码的 `mockTargets`（来自 `src/data/mockResults.ts`） |
| 后端 | **没有 targets 表** —— `sql/` 下 8 个建表脚本里没有它；也**没有 `/api/targets` 接口** |
| DTI 预测 | 靶点写死为 `P00533/EGFR`，用户无法选择靶点 |

#### 接口字段规格（严格对齐 `src/types/index.ts` 的 `Target`）

| 字段 | 必填 | 说明 | 示例 |
|---|---|---|---|
| `uniprotId` | ✅ | UniProt 登录号，**同时作为 `targetId` 传给预测接口** | `Q9BYF1` |
| `name` | ✅ | 英文名 | `ACE2` |
| `pdbId` | ✅ | PDB 结构 ID | `6M0J` |
| `description` | ✅ | 功能描述 | `血管紧张素转化酶 2，SARS-CoV-2 进入宿主细胞的功能受体…` |
| `status` | ✅ | 取值 `supported` / `beta` / `planned` | `supported` |
| `geneName` | 可选 | 基因名 | `ACE2` |
| `organism` | 可选 | 建议用 `human` / `mouse` / `virus` 等 | `human` |
| `pdbIds` | 可选 | 多个 PDB ID（优先于 `pdbId` 展示） | `["6M0J","6VW1"]` |
| `chineseName` | 可选 | 中文名 | `血管紧张素转化酶 2` |
| `targetType` | 可选 | **前端筛选项**，如 受体酪氨酸激酶 / 离子通道 | `锌金属蛋白酶（跨膜）` |
| `family` | 可选 | 蛋白家族 | `血管紧张素转化酶家族（ACE 家族）` |
| `pathway` | 可选 | 主要通路 | `肾素-血管紧张素系统（RAS）` |
| `diseaseArea` | 可选 | **前端筛选项**，如 肿瘤 / 感染 / 代谢 / 神经 / 心血管 | `心血管 · 感染` |
| `relatedDiseases` | 可选 | 相关疾病 | `高血压；SARS-CoV-2 感染` |
| `knownDrugs` | 可选 | 相关药物 / 干预方式 | `mRNA 疫苗、中和抗体` |

> ⚠️ **`Target` 接口里没有"蛋白序列"字段**，但 DTI 预测**必须**传序列
> （输入格式为 `SMILES,蛋白序列`）。
> 所以后端建表时**需要额外增加一列 `sequence TEXT`**，否则"从靶点库选靶点 → 做 DTI 预测"
> 这条路径仍然走不通。

#### 数据来源建议

| 来源 | 用途 |
|---|---|
| UniProt REST API | 一次拿全 ID / 名称 / 基因名 / 物种 / 长度 / 序列 |

```
https://rest.uniprot.org/uniprotkb/search
    ?query=reviewed:true+AND+organism_id:9606
    &fields=accession,id,protein_name,gene_names,organism_name,length,sequence,xref_pdb
    &format=tsv&size=200
```

| 来源 | 用途 |
|---|---|
| `xref_pdb` 字段 | 直接给出 PDB ID，无需再查 RCSB |
| `protein_name` | 对应 `name`（如需中文名需另行整理或人工补充） |
| 人工补充 | `targetType` / `family` / `pathway` / `diseaseArea` 等分类字段，UniProt 不直接提供 |

**建议规模**：**先做 20~50 条**即可。
要求能覆盖到多个 `targetType` 与 `diseaseArea`，否则前端的两个筛选下拉只有一个选项，失去意义。

### 2.C 边界 / 异常样本

| 样本 | 构造方式 | 期望行为 |
|---|---|---|
| 空文件 | 只有表头、无数据行 | `totalCount = 0`，批次直接 SUCCESS |
| 错表头 | 表头写成 `a,b,c` | 行数正确，但每行解析失败并逐行报错 |
| 列数不足 | 只有 1 列 | `CsvUtils.parseLine` 返回 null → 该行跳过 |
| SMILES 含逗号且已加引号 | `"CC(=O)O,xx",SEQ` | `parseCsvLine` 正确处理引号内的逗号 |
| **DDI 图外药物** | `DB99999,DB00880` | **行级** `DRUG_NOT_SUPPORTED`，**不是整批失败** |
| 非法 SMILES | `NOT_A_SMILES,SEQ` | 行级 `INVALID_SMILES` |
| 超长 SMILES | > 2000 字符 | 行级 `INPUT_RESOLVE_FAILED`（`MAX_SMILES_LENGTH = 2000`） |
| 超长序列 | 10 万字符 | ⚠️ **目前只校验下限（≥31 残基），没有上限校验** —— 正好用它验证是否需要补上限 |
| 超大文件 | >100 MB | 后端应拒绝；**注意 nginx 1MB 限制会先拦住**（见问题总账 `A-07`） |
| 非法编码 | GBK 编码的 CSV | 不应 500，应给出可读错误 |

> ✅ 这一项**我也可以代做**。

### 2.D 数据库种子 SQL（`sql/seed/`）

#### 现状（`sql/07_test_data.sql`）

只有：**1 个管理员**、**3 个任务**（2 × `completed` + 1 × `pending`）、**2 条结果**（都是 `high`）。
前端"任务中心按状态分页""结果页按置信度筛选"这类功能**没有数据可展示**。

#### 需要覆盖的组合

| 表 | 需要覆盖 | 对应来源 |
|---|---|---|
| `sys_user` | `admin` / `user` / `guest` **三种角色**；`status` = 1 与 0；`email_verified` = 0 与 1；`register_type` = `qq_email` / `phone` / `wechat` | `01_sys_user.sql` |
| `predict_task` | **五种状态全齐**：`pending` / `running` / `completed` / `failed` / `cancelled`；三种 `predict_type`（`dti`/`ppi`/`ddi`）；四种 `input_type`（`smiles`/`pdb`/`uniprot`/`csv`）；`failed` 行**必须带 `error_message`** | `03_predict_task.sql` |
| `predict_result` | **三档置信度全齐**：`high` / `medium` / `low`；`binding_affinity` 有值 与 NULL（PPI 本来就没有亲和力）；`interactions` JSON 有值 与 `[]` | `04_predict_result.sql` |
| `batch_task` | **四种状态全齐**：`0` PENDING / `1` PROCESSING / `2` SUCCESS / `3` FAIL；三种 `algo_type`；`success_count + fail_count` 与 `total_count`、`progress` **必须自洽**；FAIL 行带 `error_msg` | `06_batch_task.sql` |
| `batch_task_item` | 与 `batch_task` 配套；含 `status=3` 且带 `error_code` / `error_message` 的行 | `09_batch_task_item.sql` |
| `user_favorite` | 至少 2 个用户各有收藏；`note` 有值 与 NULL 各一 | `05_user_favorite.sql` |
| `ddi_supported_drug` | ✅ 已由 `10_ddi_supported_drug.sql` 提供 1323 条 | — |
| `sys_login_log` | 若干条登录记录（个人中心"登录记录"页用） | `02_sys_login_log.sql` |

#### ⚠️ 写种子 SQL 时的注意点

1. **有外键，必须按顺序插入**：
   `sys_user` → `predict_task` → `predict_result` → `batch_task` → `batch_task_item`
2. **不要只写死自增 id**：`predict_result.task_id` 等外键列必须真实指向已插入的行，
   建议显式指定 id 或使用子查询。
3. `batch_task_item` 的唯一键是 `(batch_id, row_number)`，注意 `row_number` **是 MySQL 保留字**，
   写 SQL 时必须加反引号：`` `row_number` ``。
4. **幂等性**：现有 `sql/01`~`06` 全是 `DROP TABLE IF EXISTS`，种子脚本**不要**沿用这个模式
   （会清库）。建议独立放在 `sql/seed/`，用 `INSERT ... ON DUPLICATE KEY UPDATE` 或先 `DELETE` 指定 id。
5. `07_test_data.sql` 建议改为**不自动执行**（从 `sql/` 移到 `sql/dev-seed/`），
   `deploy/` 的 initdb 只挂建表脚本 —— 避免生产环境被塞测试数据。

## 3. 各算法输入格式速查（易错点）

| 算法 | 输入 | **易错点** |
|---|---|---|
| DTI（KAN-MoDTI） | SMILES + **蛋白序列**（不是 UniProt ID） | 传 UniProt ID 会失败，必须先解析成序列 |
| DDI（DDI-LLM） | **DrugBank ID**（如 `DB00880`），不是 SMILES | 前端传 SMILES → 由后端 `DdiDrugResolver` 转换成 DrugBank ID；**图外药物不可预测**（共 1323 个可预测） |
| PPI（FlashPPI） | 两条**蛋白序列** | 不是蛋白名，也不是 UniProt ID |

边界速查：

- DDI 可预测药物总数：**1323**（可通过 `GET /api/predict/ddi/drugs` 获取）
- 蛋白序列长度：**下限 31 残基**（`ProteinSequenceValidator.MIN_SEQUENCE_LENGTH = 31`），**无上限校验**
- SMILES 长度：**上限 2000 字符**（`PredictionInputResolver.MAX_SMILES_LENGTH = 2000`）
- 批量分块大小：50（`BatchProcessServiceImpl.CHUNK_SIZE`）
- 单文件上传上限：**后端 100 MB / nginx 1 MB** —— 两者不一致，nginx 会先拦（问题总账 `A-07`）

### 可控错误码全表（`PredictionErrorCode`）

写异常样本时直接用这些码做断言对象：

| 错误码 | 含义 |
|---|---|
| `INPUT_RESOLVE_FAILED` | 输入解析失败（含未知算法类型、输入过长） |
| `UNIPROT_NOT_FOUND` | UniProt 条目不存在 |
| `PDB_NOT_FOUND` | PDB 结构不存在 |
| `CHAIN_NOT_FOUND` | PDB 结构中不存在指定链 |
| `INVALID_SEQUENCE` | 蛋白质序列不合法（非氨基酸字符） |
| `SEQUENCE_TOO_SHORT` | 序列长度 < 31 残基 |
| `INVALID_SMILES` | SMILES 表达式不合法 |
| `DRUG_NOT_SUPPORTED` | 药物不在 DDI 支持的 1323 个之内 |
| `FASTAPI_UNAVAILABLE` | 算法引擎不可用 |
| `MODEL_UNAVAILABLE` | 模型服务不可用（权重缺失等） |

## 4. 验收标准：怎么算"测试数据齐了"

| 检查项 | 通过标准 |
|---|---|
| 靶点库 | `GET /api/targets` 返回 ≥20 条；每条都有 `uniprotId` + `name` + `sequence`；`targetType` 与 `diseaseArea` 各 ≥3 种取值 |
