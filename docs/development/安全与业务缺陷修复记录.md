## 二、业务正确性（5 项）

| ID | 问题 | 解决方案 |
|---|---|---|
| A-06 | 批量"全失败"批次仍报 SUCCESS | 收尾按**最终行级统计**定状态：全失败→FAIL(3)、部分失败→**PARTIAL(4，新增)**、全成功→SUCCESS(2)；`getBatchStatus` 增加 `case 4 -> "PARTIAL"`（前端暂显示 UNKNOWN，下一轮补文案） |
| D-05 | 单条预测在事务内阻塞调用引擎 30~60s | `predict()` 去掉 `@Transactional`，推理在事务外执行，落库为短事务本地插入 |
| C-07 | 无幂等 + 保存失败静默 | 计算指纹 `sha256(userId\|algoType小写\|归一化输入)`，命中直接复用已有结果；`predict_result.fingerprint` 列 + 唯一索引 DB 兜底；保存失败抛 `SYSTEM_ERROR` |
| D-01 | `drugASmiles` 命名与语义不符 | 改名 `drugAInput/drugBInput`（实际可传 SMILES/DrugBank ID/药物名） |
| C-05/C-06/C-10 | 假数据死代码（Random 造假、必失败的 executeTask、无引用的置信度枚举） | 删除 `PredictUtils`、`TaskService.executeTask`、`TaskServiceImpl.executeTask`、`ConfidenceLevel` |

## 六、运维与迁移说明（使用者必读）

1. **已有数据库迁移**：老库需手工执行 `sql/11_sys_user_research_profile.sql` 与 `sql/12_security_consistency.sql`（新库/docker 空卷自动执行）；不执行则登录后所有接口 401（缺 `token_version` 列）
2. **部署必填环境变量**（deploy/.env，start 脚本自动补随机值）：`MYSQL_ROOT_PASSWORD`、`MYSQL_PASSWORD`、`JWT_SECRET`、`RABBITMQ_PASSWORD`
3. **本地启动**：需显式 `SPRING_PROFILES_ACTIVE=dev` + `DB_PASSWORD` 环境变量（README 已更新）
4. **邮箱功能**：仓库不含邮箱凭据，在 .env 配置自己的 SMTP 邮箱（`QQ_EMAIL`/`QQ_EMAIL_AUTH_CODE`，任意邮箱均可）；本地测试可用 `CAPTCHA_DEV_MODE=true` 回显验证码；不配置则游客登录 + 全部预测功能照常可用
5. **凭据轮换**：git 历史中仍存在旧 MySQL 密码与 QQ 授权码，上线/公开仓库前必须轮换（改 MySQL 密码、重新生成 QQ 授权码），旧值在轮换前一直有效
