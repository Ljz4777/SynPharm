# SynPharm 未实现功能修复技术方案

## 1. 文档目的

本文针对 SynPharm 当前前端、Spring Boot Java 后端和 FastAPI Python 后端之间存在的接口断裂、功能闲置和数据闭环缺失问题，给出可实施的修复方案。

当前最优先的问题是：前端使用 UniProt ID 或 PDB ID，Java 解析器目前主要进行字符串切分，而 FastAPI 的 DTI/PPI 模型需要真实的蛋白质氨基酸序列。因此接口虽然可以调用，但核心输入语义并未打通。

## 2. 总体修复策略

1. 统一单条预测入口和请求契约。
2. Java 完成 UniProt/PDB ID 到蛋白质序列的解析、校验和缓存。
3. Python 只接收标准化后的序列或 SMILES，负责算法校验和推理。
4. 补齐收藏、批量任务和结果查询的数据闭环。
5. 处理无真实数据的 interactions、binding affinity 和 Targets 页面。
6. 最后清理 RabbitMQ、重复 API 封装、废弃接口和外部数据直连等技术债。

## 3. 当前关键问题

| 优先级 | 问题 | 主要影响 |
|:---|:---|:---|
| P0 | UniProt/PDB ID 没有转换为蛋白质序列 | DTI/PPI 按页面提示输入时可能直接失败 |
| P0 | 前端仍调用 `/api/predict/dti`、`/ppi`、`/ddi` | 统一管道接口 `/api/predict/general` 未成为主入口 |
| P1 | 后端收藏接口已存在，前端没有调用 | 收藏功能对用户不可用 |
| P1 | 批量结果主要写 CSV 和 `batch_task` | 任务中心、结果中心看不到批量结果 |
| P1 | interactions 恒为空，DTI affinity 不提供回归值 | 前端展示区域长期为空或产生误解 |
| P1 | Targets 页面使用 Mock 数据 | 页面数据不能代表真实靶点库 |
| P2 | RabbitMQ 与 `@Async` 方案重复 | 架构和运行方式不一致 |
| P2 | FastAPI 健康接口没有 Java 主动探活 | 算法引擎故障只能等预测超时后发现 |
| P2 | 前端存在重复任务 API 封装 | 维护成本增加，行为容易不一致 |

## 4. 前端修复方案

### 4.1 统一预测 API

修改：

- `synpharm-frontend/src/api/predict.ts`
- `synpharm-frontend/src/views/Predict.vue`
- `synpharm-frontend/src/views/Home.vue`

统一使用：

```text
POST /api/predict/general
```

请求类型：

```ts
export type PredictInputType =
  | 'smiles'
  | 'uniprot'
  | 'pdb'
  | 'sequence'
  | 'csv'

export type PredictAlgoType = 'DTI' | 'PPI' | 'DDI'

export interface GeneralPredictRequest {
  inputType: PredictInputType
  algoType: PredictAlgoType
  inputValue: string
  outputType?: 'json' | 'csv'
  fileUrl?: string
}
```

请求示例：

```json
{
  "inputType": "uniprot",
  "algoType": "DTI",
  "inputValue": "CCO,P0DTC2",
  "outputType": "json"
}
```

`selectedInputType` 必须真实写入请求体，不能只用于修改页面提示。

### 4.2 输入校验和提示

| 算法 | 输入类型 | 输入内容 |
|:---|:---|:---|
| DTI | `uniprot` | 配体 SMILES、UniProt ID |
| DTI | `pdb` | 配体 SMILES、PDB ID 和可选链号 |
| DTI | `sequence` | 配体 SMILES、氨基酸序列 |
| PPI | `uniprot` | 两个 UniProt ID |
| PPI | `sequence` | 两条氨基酸序列 |
| DDI | `smiles` | 两个药物 SMILES |

前端错误提示至少覆盖：无法找到 UniProt/PDB 数据、序列格式错误、序列长度不足、模型不可用和 FastAPI 服务不可用。

### 4.3 收藏功能

新增 `src/api/favorite.ts`，封装：

```text
POST   /api/favorites
DELETE /api/favorites/{resultId}
GET    /api/favorites/{resultId}/status
GET    /api/favorites
```

修改 `ResultCard.vue`、`Results.vue` 和路由配置，并新增收藏列表页面。收藏按钮需要处理已收藏、未收藏、请求中和失败回滚四种状态。

### 4.4 批量任务和 Targets 页面

批量页面需要支持任务列表、状态进度、成功数、失败数、失败原因、结果下载和页面刷新后恢复查询。

Targets 页面建议接入：

```text
GET /api/targets
GET /api/targets/{id}
GET /api/targets/search
```

真实接口完成前，应明确显示示例数据，避免用户将 Mock 靶点用于真实预测。

## 5. Java Spring Boot 后端修复方案

### 5.1 统一预测入口

当前已有 `GeneralPredictRequest`、`PredictService.predict()` 和管道工厂，应将其作为主链路：

```text
POST /api/predict/general
```

旧的 `/dti`、`/ppi`、`/ddi` 暂时保留为兼容接口，但内部统一转换为 `GeneralPredictRequest`，并标记为 deprecated。

涉及文件：

- `synpharm-backend/src/main/java/com/synpharm/dto/request/GeneralPredictRequest.java`
- `synpharm-backend/src/main/java/com/synpharm/service/impl/PredictServiceImpl.java`
- `PredictController`

### 5.2 建立标准化输入模型

新增 `ResolvedPredictionInput`，至少包含：

```text
algoType
inputType
ligandSmiles
targetSequence
proteinA
proteinB
drugA
drugB
targetId
targetName
```

新增服务：

```text
prediction/PredictionInputResolver.java
prediction/UniProtResolver.java
prediction/PdbResolver.java
prediction/ProteinSequenceValidator.java
prediction/ResolvedPredictionInput.java
```

### 5.3 UniProt 和 PDB 解析

DTI 流程：

```text
SMILES + UniProt ID -> 查询 UniProt REST API -> 获取序列 -> 校验 -> 调用 FastAPI
```

PPI 流程：

```text
两个 UniProt ID -> 分别查询序列 -> 校验 -> 调用 FastAPI
```

PDB 流程：

```text
PDB ID/链号 -> 查询 RCSB 结构数据 -> 获取链的 FASTA 序列 -> 校验并缓存 -> 调用 FastAPI
```

建议支持 `6M0J:A` 形式的输入，避免只把 PDB ID 当作蛋白质序列发送给模型。

### 5.4 外部数据缓存和超时

建议使用 Redis 缓存：

```text
synpharm:uniprot:{id}
synpharm:pdb:{id}:{chain}
```

配置示例：

```yaml
prediction:
  resolver:
    uniprot-base-url: https://rest.uniprot.org
    rcsb-base-url: https://data.rcsb.org
    connect-timeout-ms: 3000
    read-timeout-ms: 5000
    cache-ttl-hours: 24
```

### 5.5 错误码

建议统一使用：

```text
INPUT_RESOLVE_FAILED
UNIPROT_NOT_FOUND
PDB_NOT_FOUND
CHAIN_NOT_FOUND
INVALID_SEQUENCE
SEQUENCE_TOO_SHORT
INVALID_SMILES
FASTAPI_UNAVAILABLE
MODEL_UNAVAILABLE
```

示例：

```json
{
  "code": "SEQUENCE_TOO_SHORT",
  "message": "蛋白质序列长度不足，至少需要 31 个残基",
  "data": null
}
```

### 5.6 批量数据闭环

建议新增 `batch_task_item` 表，保存每一行输入、状态、错误信息和结果 ID：

```text
batch_id
row_number
input_value
status
result_id
error_code
error_message
created_at
updated_at
```

处理流程：

```text
上传 CSV -> 创建 batch_task -> 创建 batch_task_item -> 异步预测
-> 保存 predict_result -> 回写 result_id -> 更新 batch_task 统计
```

这样任务中心和结果中心才能查询批量数据，而不是只能依赖当前页面轮询和 CSV 下载。

### 5.7 收藏和健康检查

收藏功能需要保证：按用户隔离、重复收藏幂等、删除时校验结果归属，并为 `user_id + result_id` 增加唯一约束。

建议增加：

```text
GET /api/system/algorithm-health
```

Java 内部主动调用 FastAPI `/health/`，并配置连接超时、响应超时、有限重试和熔断。

### 5.8 RabbitMQ 方案选择

必须在 `@Async` 和 RabbitMQ 中选择一个主方案。小规模部署可保留 `@Async` 并清理 RabbitMQ 死代码；生产环境建议正式启用 RabbitMQ，并补充重试、死信、幂等、取消标记和服务重启恢复。

## 6. Python FastAPI 后端修复方案

### 6.1 保持输入职责清晰

推荐由 Java 完成 UniProt/PDB ID 解析，FastAPI 只接收标准输入并执行模型推理。

DTI：

```json
{
  "algo_type": "DTI",
  "drug_smiles": "CCO",
  "target_seq": "MKT..."
}
```

PPI：

```json
{
  "algo_type": "PPI",
  "protein_a": "MKT...",
  "protein_b": "MPE..."
}
```

DDI：

```json
{
  "algo_type": "DDI",
  "drug_a": "CCO",
  "drug_b": "CCN"
}
```

### 6.2 序列校验

在 `core/schemas.py` 和算法服务层增加去除空格、转大写、最小长度、非法字符和必填字段校验。

允许的标准氨基酸字符：

```text
ACDEFGHIKLMNPQRSTVWY
```

DTI/PPI 序列不足 31 个残基时返回 `SEQUENCE_TOO_SHORT`。

### 6.3 统一错误响应

建议修改 `core/exceptions.py`、`main.py` 和 `api/v1/predict.py`，返回：

```json
{
  "code": "INVALID_SEQUENCE",
  "message": "蛋白质序列包含非法字符",
  "details": {
    "field": "target_seq"
  }
}
```

状态码建议：参数结构错误为 422，输入内容非法为 400，API Key 错误为 401，模型不可用为 503，未预期异常为 500。

### 6.4 interactions 和 binding affinity

当前模型没有真实残基级解释时，不应伪造 interactions。建议增加：

```json
{
  "interactions": [],
  "explanation_available": false,
  "explanation_message": "当前模型仅提供整体预测分数"
}
```

DTI 当前是二分类模型时，`binding_affinity` 保持 `null`，增加 `binding_affinity_available: false`，前端不要把 `confidence_score` 当成亲和力。

### 6.5 模型健康检查

模型懒加载需要增加加载锁、失败状态和模型就绪状态。`/health/` 建议返回：

```json
{
  "status": "ready",
  "models": {
    "DTI": "ready",
    "PPI": "ready",
    "DDI": "ready"
  }
}
```

区分服务存活和模型是否就绪，避免 Docker 显示健康但实际无法预测。

### 6.6 批量接口结果

批量接口应逐行返回成功或失败原因：

```json
{
  "status": "success",
  "total": 2,
  "success_count": 1,
  "fail_count": 1,
  "results": [
    {
      "row_number": 1,
      "status": "success",
      "metrics": {}
    },
    {
      "row_number": 2,
      "status": "failed",
      "error_code": "INVALID_SEQUENCE",
      "error_message": "蛋白质序列长度不足"
    }
  ]
}
```

## 7. 推荐实施顺序

### 第一阶段：修复单条预测

1. 前端接入 `/api/predict/general`。
2. Java 完善统一请求和解析流程。
3. 实现 UniProt 查询、PDB 链序列获取和缓存。
4. Java 将标准化字段发送给 FastAPI。
5. FastAPI 增加输入校验和错误码。
6. 完成 DTI、PPI、DDI 单条联调。

### 第二阶段：补齐用户功能

1. 接入收藏接口和收藏列表。
2. 增加批量任务明细表。
3. 将批量结果关联到任务中心和结果中心。
4. 增加批量失败原因查询。

### 第三阶段：修复展示和可用性

1. 对 interactions 和 binding affinity 做能力标记。
2. Targets 接入真实 API 或明确标记为示例数据。
3. 增加 FastAPI 模型健康状态。
4. 增加 UniProt/PDB 外部数据缓存。

### 第四阶段：清理技术债

1. 确定 `@Async` 或 RabbitMQ 的唯一主方案。
2. 清理废弃预测端点。
3. 合并前端重复任务 API。
4. 清理无调用路径的 CSV 组件。
5. 为结构数据增加后端代理或缓存。

## 8. 验收标准

### 前端

- 选择输入类型后，`inputType` 真实出现在请求体中。
- UniProt ID 能完成 DTI/PPI 预测。
- PDB ID 能指定链并完成预测。
- 输入错误时显示明确原因。
- 收藏和取消收藏可用。
- 批量任务刷新页面后仍可查询。

### Java 后端

- `/api/predict/general` 成为单条预测主入口。
- UniProt/PDB 不再只是字符串切分。
- 发送给 FastAPI 的是有效蛋白质序列。
- 外部数据具有缓存、超时和失败处理。
- 批量结果可关联任务和结果表。
- 用户只能访问自己的任务、结果和收藏。

### Python 后端

- DTI/PPI 接收有效蛋白质序列。
- 非法序列返回明确错误码。
- 模型不可用返回 503。
- interactions 不返回伪造数据。
- binding affinity 不可用时有明确标记。
- 批量接口逐条返回成功或失败原因。
- `/health/` 能区分服务状态和模型状态。

## 9. 测试要求

### 前端测试

- 不同 `inputType` 生成正确请求体。
- DTI、PPI、DDI 分别调用统一接口。
- 收藏按钮状态切换正确。
- 批量任务轮询和页面刷新恢复正确。

### Java 测试

- UniProt 正常查询、ID 不存在和外部超时。
- PDB 正常查询、链不存在和结构不存在。
- 序列长度和字符校验。
- FastAPI 请求字段映射。
- 批量任务明细和用户数据隔离。

### Python 测试

- DTI/PPI 缺少序列返回 400。
- 非法序列返回 `INVALID_SEQUENCE`。
- 短序列返回 `SEQUENCE_TOO_SHORT`。
- 模型缺失返回 503。
- 批量结果逐条返回状态。
- 健康检查正确反映模型状态。
