## 1. 部署流程

### 1.1 部署前检查清单

| 检查项 | 说明 | 验证方法 |
|:---|:---|:---|
| 依赖版本 | Java 21+, Python 3.10+, MySQL 8.0+, Redis 7.0+ | `java -version`, `python --version`, `mysql --version`, `redis-cli ping` |
| 数据库配置 | 数据库已创建，用户权限正确 | `mysql -u synpharm -p -e "SELECT 1"` |
| Redis配置 | Redis可连接，无密码或密码正确 | `redis-cli ping` |
| 模型文件 | FastAPI models目录下有模型文件 | `ls synpharm-fastapi/models/` |
| 环境变量 | `.env` 文件配置正确 | 检查各模块 `.env` 文件 |
| 端口占用 | 8080/8000/80端口未被占用 | `netstat -tlnp \| grep 8080` |

### 1.2 部署步骤（开发环境）

#### 步骤1：启动基础服务

```bash
# 启动MySQL
systemctl start mysql
# 或 Docker
docker run -d --name mysql -p 3306:3306 -e MYSQL_ROOT_PASSWORD=synpharm_root mysql:8.0

# 启动Redis
systemctl start redis
# 或 Docker
docker run -d --name redis -p 6379:6379 redis:7-alpine
```

#### 步骤2：启动后端服务

```bash
cd synpharm-backend
mvn clean package -DskipTests
java -jar target/synpharm-backend-1.0.0.jar
```

验证：`curl http://localhost:8080/api/auth/captcha/send -X POST -H "Content-Type: application/json" -d '{"email":"test@qq.com","type":"login"}'`

#### 步骤3：启动FastAPI服务

```bash
cd synpharm-fastapi
python -m venv venv
source venv/bin/activate
pip install -r requirements.txt
uvicorn main:app --host 0.0.0.0 --port 8000
```

验证：`curl http://localhost:8000/health`

#### 步骤4：启动前端服务

```bash
cd synpharm-frontend
npm install
npm run dev
```

验证：访问 `http://localhost:5174`

## 2. Git分支策略与合并规范

### 2.1 分支结构

```
main                    ← 生产分支（稳定代码）
├── develop             ← 开发分支（集成所有功能）
│   ├── feature/ppi-algo-executor     ← 功能分支
│   ├── feature/ddi-algo-executor     ← 功能分支
│   ├── feature/uniprot-input-parser  ← 功能分支
│   ├── fix/auth-bug                  ← 修复分支
│   └── hotfix/紧急修复               ← 热修复分支
```

### 2.2 分支命名规范

| 分支类型 | 命名格式 | 示例 |
|:---|:---|:---|
| 功能开发 | `feature/{模块}-{功能}` | `feature/ppi-algo-executor`, `feature/uniprot-input-parser` |
| Bug修复 | `fix/{模块}-{问题描述}` | `fix/auth-captcha-error`, `fix/pipeline-batch-process` |
| 热修复 | `hotfix/{问题描述}` | `hotfix/login-failure`, `hotfix/api-timeout` |
| 重构 | `refactor/{模块}-{描述}` | `refactor/auth-unify-login`, `refactor/pipeline-factory` |
| 文档 | `docs/{描述}` | `docs/deployment-guide`, `docs/api-spec` |

### 2.3 分支创建与合并流程

#### 流程1：功能开发

```bash
# 1. 从develop拉取最新代码
git checkout develop
git pull origin develop

# 2. 创建功能分支
git checkout -b feature/ppi-algo-executor

# 3. 开发代码（多次提交）
git add .
git commit -m "feat: pipeline 添加PPI算法执行器"
git add .
git commit -m "test: pipeline 添加PPI算法执行器单元测试"

# 4. 推送到远程
git push origin feature/ppi-algo-executor

# 5. 在GitHub创建PR（Pull Request）
# 目标分支：develop

# 6. 代码审查通过后合并到develop
# GitHub自动完成合并
```

#### 流程2：Bug修复

```bash
# 1. 从develop拉取最新代码
git checkout develop
git pull origin develop

# 2. 创建修复分支
git checkout -b fix/auth-captcha-error

# 3. 修复代码
git add .
git commit -m "fix: auth 修复验证码发送失败问题"

# 4. 推送并创建PR
git push origin fix/auth-captcha-error
```

#### 流程3：热修复（紧急问题）

```bash
# 1. 从main拉取代码（直接从生产分支创建）
git checkout main
git pull origin main

# 2. 创建热修复分支
git checkout -b hotfix/login-failure

# 3. 修复代码
git add .
git commit -m "hotfix: 紧急修复登录接口500错误"

# 4. 推送到远程并创建PR
git push origin hotfix/login-failure

# 5. 合并到main和develop
# PR目标：main
# 合并后再合并到develop
```

### 2.4 提交信息规范

#### 格式

```
{类型}: {模块} {功能描述}

{详细说明（可选）}

{关联的Issue或PR编号}
```

#### 类型说明

| 类型 | 说明 |
|:---|:---|
| `feat` | 新功能（新增接口、新增类、新增功能） |
| `fix` | 修复Bug |
| `refactor` | 重构代码（不改变功能） |
| `docs` | 更新文档 |
| `test` | 添加/修改测试 |
| `chore` | 构建/工具/配置变更 |
| `hotfix` | 紧急修复 |

#### 示例

```
feat: pipeline 添加PPI算法执行器

- 实现PpiAlgoExecutor类
- 调用FastAPI执行PPI预测
- 添加单元测试

Closes #123
```

```
fix: auth 修复游客登录失败问题

- 修复GuestLoginStrategy中用户创建逻辑
- 添加游客登录的异常处理

Closes #124
```

```
refactor: predict 统一预测接口

- 废弃旧的predictDTI/PPI/DDI方法
- 统一使用predict通用方法

Closes #125
```

### 2.5 代码审查要求

| 审查项 | 要求 |
|:---|:---|
| 代码风格 | 符合项目规范，无未使用的import |
| 单元测试 | 核心逻辑必须有单元测试 |
| 错误处理 | 有完善的异常处理和日志 |
| 安全性 | 无SQL注入、XSS等安全问题 |
| 文档 | 新增接口有Swagger注解 |

### 2.6 版本标签规范

```bash
# 创建版本标签
git tag v1.0.0
git push origin v1.0.0

# 标签命名格式
v{主版本}.{次版本}.{修订版本}

# 示例
v1.0.0    # 第一个正式版本
v1.1.0    # 新增功能
v1.1.1    # 修复Bug
v2.0.0    # 重大重构
```

// 文件: src/stores/auth.test.ts
import { describe, it, expect, vi, beforeEach } from 'vitest'
import { setActivePinia, createPinia } from 'pinia'
import { useAuthStore } from './auth'
import { authApi } from '@/api/auth'

vi.mock('@/api/auth', () => ({
  authApi: {
    login: vi.fn(),
    logout: vi.fn(),
    sendCaptcha: vi.fn(),
    resetPassword: vi.fn()
  }
}))

describe('Auth Store', () => {
  beforeEach(() => {
    setActivePinia(createPinia())
    vi.clearAllMocks()
  })

  it('should login successfully', async () => {
    const mockUser = { id: '1', email: 'test@qq.com', nickname: 'Test', createdAt: '2024-01-01' }
    ;(authApi.login as vi.Mock).mockResolvedValue({ token: 'token', user: mockUser })

    const store = useAuthStore()
    const result = await store.login({ loginType: 'qq_email', email: 'test@qq.com', captcha: '123456' })

    expect(result.success).toBe(true)
    expect(store.user).toEqual(mockUser)
    expect(store.token).toBe('token')
    expect(store.isLoggedIn).toBe(true)
  })

  it('should login as guest', async () => {
    const mockUser = { id: 'guest_1', email: 'guest@guest.local', nickname: '游客', createdAt: '2024-01-01' }
    ;(authApi.login as vi.Mock).mockResolvedValue({ token: 'guest_token', user: mockUser })

    const store = useAuthStore()
    const result = await store.login({ loginType: 'guest' })

    expect(result.success).toBe(true)
    expect(store.isGuest).toBe(true)
  })

  it('should logout successfully', async () => {
    const store = useAuthStore()
    store.user = { id: '1', email: 'test@qq.com', nickname: 'Test', createdAt: '2024-01-01' }
    store.token = 'token'
    store.isLoggedIn = true

    await store.logout()

    expect(store.user).toBeNull()
    expect(store.token).toBeNull()
    expect(store.isLoggedIn).toBe(false)
  })

  it('should send captcha', async () => {
    ;(authApi.sendCaptcha as vi.Mock).mockResolvedValue({ success: true })

    const store = useAuthStore()
    const result = await store.sendCaptcha('test@qq.com', 'login')

    expect(result.success).toBe(true)
    expect(authApi.sendCaptcha).toHaveBeenCalledWith('test@qq.com', 'login')
  })

  it('should reset password', async () => {
    ;(authApi.resetPassword as vi.Mock).mockResolvedValue()

    const store = useAuthStore()
    const result = await store.resetPassword('test@qq.com', '123456', 'newPassword')

    expect(result.success).toBe(true)
    expect(authApi.resetPassword).toHaveBeenCalledWith('test@qq.com', '123456', 'newPassword')
  })
})
