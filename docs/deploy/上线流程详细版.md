上线前要解决的核心问题浓缩为 **6 项**，逐项打勾后即可对照下方详细阶段执行。

| # | 核心问题 | 一句话结论 | 详细阶段 | 状态 |
|---|---|---|---|---|
| 1 | **租服务器** | 云厂商 + 规格（起步 2C4G）；国内服务器需 **ICP 备案（1~3 周，务必提前）** | 阶段 0 / 阶段 4 | ☐ |

| 3 | **连接数据库** | 容器 MySQL 或云 RDS；执行 `sql/` 建表脚本；`.env` 配 `DB_*`；配每日备份 | 阶段 5 / 阶段 6 | ☐ |
| 4 | **邮箱验证** | QQ 邮箱 SMTP + 授权码即可（**不用买**）；要正式发件域名才上企业邮箱 | 阶段 1（邮件配置） | ☐ |

**易遗漏但必做：** 域名 + HTTPS（阶段 5）、数据库备份与恢复演练（阶段 6）、监控告警（阶段 6）、CI/CD 流水线（阶段 3）。

# 阶段 0：前置决策（详细）

## 0.1 服务器选型

| 场景 | 规格建议 | 月成本参考（云厂商普通机型） |
|---|---|---|
| 演示/小流量（≤100 并发） | 2C 4G，40G SSD，固定带宽 3Mbps | 约 ¥150~300 |
| 正式对外（100~500 并发） | 4C 8G，80G SSD，按量带宽 5Mbps | 约 ¥400~800 |
| AI 推理量大 | 在上述基础上加 GPU（如 T4/A10）或独立推理节点 | GPU 另计 |

**决策树：**
```
模型推理慢？（单条 > 5s）？
├─ 否 → 纯 CPU 机型即可，FastAPI 用 DEVICE=cpu
└─ 是 → 上 GPU 机型，DEVICE=cuda:0
         （需服务器装 NVIDIA 驱动 + nvidia-container-toolkit，见 4.5）
```

## 0.2 域名与备案（国内服务器必做）

| 步骤 | 耗时 | 说明 |
|---|---|---|
| 注册域名（如 `synpharm.com` / `.cn`） | 即时 | 建议同时买好 HTTPS 证书或走免费证书 |
| **ICP 备案**（阿里云/腾讯云控制台提交） | **1~3 周** | 备案期间域名不能解析到大陆服务器对外提供服务，**提前启动** |
| 实名认证/网站信息填写 | 1~3 天 | 需营业执照（企业）或身份证（个人） |

> 若无法等待备案：可先用香港/海外服务器（免备案）过渡，正式后再切回大陆服务器。

## 0.3 镜像仓库

| 方案 | 优点 | 缺点 |
|---|---|---|
| Docker Hub（公开） | 简单 | 公开镜像所有人可拉，私密需付费 |
| 阿里云 ACR / 腾讯云 TCR | 国内拉取快，有免费额度 | 绑定云账号 |
| Harbor（自建） | 完全自控 | 需一台机器维护 |

**推荐：** 与服务器同云厂商的镜像仓库（拉取走内网，快且免费额度内够用）。

## 0.4 数据库方案决策

| 方案 | 适用 | 说明 |
|---|---|---|
| 容器 MySQL（当前 compose 方案） | 小流量起步 | 需自己配备份（见阶段 6） |
| 云 RDS MySQL | 正式稳定运行 | 自带高可用/自动备份/监控，推荐 |

> 切换 RDS 时只需改 `deploy/.env` 的 `DB_HOST/DB_PORT/DB_USERNAME/DB_PASSWORD` 指向 RDS 连接串，并保证 SQL 初始化脚本已执行。

## 1.4 AI 模型文件就位（⚠️ 静默降级陷阱）

**模型文件名（`loader.py` 硬编码，必须精确）：**
```
synpharm-fastapi/models/
├── dti_model.pt   # 药物-靶点
├── ppi_model.pt   # 蛋白质-蛋白质
└── ddi_model.pt   # 药物-药物
```

> **⚠️ 重要**：当前 `ddi_service.py`/`dti_service.py`/`ppi_service.py` 在 `get_model()` 返回 `None`（即模型缺失）时，**不会报错**，而是走 `_generate_mock_result()` 静默返回**假结果**。因此模型缺失时服务仍显示 healthy、预测仍"成功"，但结果是随机假数据——这是上线最危险的坑。

**验证模型确实加载（而非 fallback）：**
- 方案 A：临时在 `loader.py` 的 `_load_models()` 末尾加：
  ```python
  import logging; log = logging.getLogger(__name__)
  log.warning(f"已加载模型: {list(self._models.keys())}")
  ```
  启动后看日志确认 `["dti","ppi","ddi"]`。
- 方案 B（推荐，生产保留）：在 `/v1/predict/single` 返回中增加 `model_loaded` 字段，或启动时 `if not self.has_model("dti"): raise`（fail-fast）。

**功能验证（三类型各一次）：**
```bash
# DTI
curl -X POST http://localhost:8000/v1/predict/single -H "Content-Type: application/json" \
  -d '{"algo_type":"DTI","drug_smiles":"CC(=O)OC1=CC=CC=C1C(=O)O","target_seq":"MGLGLG"}'
# PPI
curl -X POST http://localhost:8000/v1/predict/single -H "Content-Type: application/json" \
  -d '{"algo_type":"PPI","protein_a":"MGLGLG","protein_b":"MVHLTE"}'
# DDI
curl -X POST http://localhost:8000/v1/predict/single -H "Content-Type: application/json" \
  -d '{"algo_type":"DDI","drug_a":"CC(=O)OC1=CC=CC=C1C(=O)O","drug_b":"C1CCCCC1"}'
# 期望：三类型均返回 status=success 且有具体数值（非每次随机波动=真实模型）
```

# 阶段 3：CI/CD 与镜像仓库（详细）

## 3.1 初始化远程仓库
```bash
# 本地（Windows）
cd d:\SynPharm
git remote add origin <仓库地址>.git
git add -A && git commit -m "chore: 上线前整改"
git push -u origin main
```

## 3.2 配置 CI Secrets（GitHub）
仓库 → Settings → Secrets and variables → Actions → New repository secret：
```
REGISTRY=<镜像仓库地址，如 registry.cn-hangzhou.aliyuncs.com/synpharm>
REGISTRY_USERNAME=<仓库用户名>
REGISTRY_PASSWORD=<仓库密码/Token>
SERVER_HOST=<服务器IP>
SERVER_USER=<服务器SSH用户>
SERVER_SSH_KEY=<服务器私钥内容>      # 可选，若启用自动部署
```

## 3.3 `.github/workflows/ci.yml`（完整内容）
```yaml
name: CI/CD

on:
  push:
    branches: [ main ]
    tags: [ 'v*' ]
  pull_request:
    branches: [ main ]

env:
  IMAGE_PREFIX: ${{ secrets.REGISTRY }}
  VERSION: ${{ startsWith(github.ref, 'refs/tags/') && github.ref_name || 'latest' }}

jobs:
  build-and-push:
    runs-on: ubuntu-latest
    strategy:
      matrix:
        service: [backend, frontend, fastapi]
    steps:
      - uses: actions/checkout@v4

      - name: Build ${{ matrix.service }}
        run: docker build -t ${{ env.IMAGE_PREFIX }}/${{ matrix.service }}:${{ env.VERSION }} ./synpharm-${{ matrix.service }}

      - name: Login registry
        run: echo "${{ secrets.REGISTRY_PASSWORD }}" | docker login ${{ secrets.REGISTRY }} -u ${{ secrets.REGISTRY_USERNAME }} --password-stdin

      - name: Push image
        run: docker push ${{ env.IMAGE_PREFIX }}/${{ matrix.service }}:${{ env.VERSION }}

  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Backend test
        run: cd synpharm-backend && mvn -B test
      - name: Frontend build
        run: cd synpharm-frontend && npm ci && npm run build
      - name: FastAPI test
        run: cd synpharm-fastapi && pip install -r requirements.txt pytest httpx && python -m pytest

  deploy:
    needs: [build-and-push, test]
    if: startsWith(github.ref, 'refs/tags/')
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Deploy via SSH
        uses: appleboy/ssh-action@v1.0.3
        with:
          host: ${{ secrets.SERVER_HOST }}
          username: ${{ secrets.SERVER_USER }}
          key: ${{ secrets.SERVER_SSH_KEY }}
          script: |
            cd /opt/SynPharm/deploy
            sed -i "s/^SYNPHARM_VERSION=.*/SYNPHARM_VERSION=${{ env.VERSION }}/" .env
            docker compose pull
            docker compose up -d
```

# 阶段 4：服务器环境准备（详细）

## 4.1 开通云服务器
- 系统镜像：Ubuntu 22.04 LTS（推荐）
- 安全组（入方向）**最小化**：

| 端口 | 协议 | 来源 | 用途 |
|---|---|---|---|
| 22 | TCP | 仅你的办公 IP | SSH（强烈建议改非默认端口） |
| 80 | TCP | 0.0.0.0/0 | HTTP |
| 443 | TCP | 0.0.0.0/0 | HTTPS |
| ~~3306/6379/8080/8000~~ | - | **不开** | 禁止公网直连 |

## 4.2 基础初始化（SSH 登录后）
```bash
# 更新系统
sudo apt update && sudo apt upgrade -y

# 安装 Docker + Compose 插件
curl -fsSL https://get.docker.com | sudo sh
sudo systemctl enable --now docker

# 验证
docker version && docker compose version
```
> 若需非 root 执行 docker：`sudo usermod -aG docker $USER` 后重新登录。

## 4.3 SSH 加固（必做）
```bash
sudo sed -i 's/^#\?PermitRootLogin.*/PermitRootLogin no/' /etc/ssh/sshd_config
sudo sed -i 's/^#\?PasswordAuthentication.*/PasswordAuthentication no/' /etc/ssh/sshd_config
# 先确认你的密钥能登录！再重启
sudo systemctl restart sshd
```

## 4.4 时区与数据盘
```bash
sudo timedatectl set-timezone Asia/Shanghai
# 若有额外数据盘：格式化后挂载到 /var/lib/docker（或创建软链），确保 Docker 数据落数据盘
sudo mkfs.ext4 /dev/vdb
sudo mkdir -p /var/lib/docker
echo '/dev/vdb /var/lib/docker ext4 defaults 0 0' | sudo tee -a /etc/fstab
sudo mount -a
```

## 4.5 GPU 支持（若选 GPU 机型）
```bash
# 安装 NVIDIA 驱动 + 容器工具
sudo apt install -y nvidia-driver-535
curl -fsSL https://nvidia.github.io/libnvidia-container/gpgkey \
  | sudo gpg --dearmor -o /usr/share/keyrings/nvidia-container-toolkit-keyring.gpg
sudo apt-get update && sudo apt-get install -y nvidia-container-toolkit
sudo nvidia-ctk runtime configure --runtime=docker && sudo systemctl restart docker
# 验证
docker run --rm --gpus all nvidia/cuda:12.0-base-ubuntu22.04 nvidia-smi
```
> 之后在 `deploy/.env` 设 `FASTAPI_DEVICE=cuda:0`，并在 compose 的 fastapi 服务加 `deploy.resources.reservations.devices`（见阶段 6.1）。

## 4.6 域名解析
- 在 DNS 控制台添加 A 记录：`synpharm.example.com → <服务器公网IP>`
- 验证：`nslookup synpharm.example.com` 返回你的 IP。

**阶段验收：** SSH 可登录、Docker 可用、`curl -I http://<IP>` 通（阶段 5 部署后 80 有响应）。


**② 前端 nginx 增加 SSL**（编辑 `synpharm-frontend/nginx.conf`，或在服务器上用卷覆盖）：
```nginx
server {
    listen 8080;
    server_name synpharm.example.com;

    root /usr/share/nginx/html;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }

    location /api/ {
        proxy_pass http://backend:8080/api/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto https;   # 关键：透传 https
    }

    location ~* \.(js|css|png|jpg|jpeg|gif|ico|svg|woff|woff2|ttf|eot)$ {
        expires 1y;
        add_header Cache-Control "public, immutable";
    }
}

# 说明：443 终止可放在前置 Nginx / 云 LB / 本容器三选一。
# 若由本容器终止，则把证书挂载并加：
#   listen 8443 ssl;
#   ssl_certificate     /etc/nginx/certs/fullchain.pem;
#   ssl_certificate_key /etc/nginx/certs/privkey.pem;
#   return 301 https://$host$request_uri;   # 80→443
```

**③ 云 LB / 前置 Nginx 终止 HTTPS（推荐，证书续期更简单）**：
- 云负载均衡绑定证书 → 443 转发到后端容器 80/8080

## 6.5 数据库备份（完整脚本）

**`deploy/scripts/backup.sh`**（每日执行）：
```bash
#!/usr/bin/env bash
set -euo pipefail
cd "$(dirname "$0")/.."
source .env

BACKUP_DIR="${BACKUP_DIR:-/opt/synpharm-backups}"
STAMP=$(date +%Y%m%d_%H%M%S)
mkdir -p "$BACKUP_DIR"

# 1) MySQL 逻辑备份（容器内执行）
docker exec synpharm-mysql mysqldump \
  -uroot -p"$MYSQL_ROOT_PASSWORD" \
  --single-transaction --routines --triggers \
  "$MYSQL_DATABASE" | gzip > "$BACKUP_DIR/mysql_$STAMP.sql.gz"

# 2) 保留最近 14 天
find "$BACKUP_DIR" -name 'mysql_*.sql.gz' -mtime +14 -delete

# 3) 同步到对象存储（阿里云 OSS / 腾讯 COS，用各自 CLI）
# ossutil cp "$BACKUP_DIR/mysql_$STAMP.sql.gz" oss://<bucket>/synpharm/ || true

echo "[OK] backup done: $BACKUP_DIR/mysql_$STAMP.sql.gz"
```

**定时任务**（crontab）：

```bash
30 2 * * * /opt/SynPharm/deploy/scripts/backup.sh >> /var/log/synpharm-backup.log 2>&1
```
