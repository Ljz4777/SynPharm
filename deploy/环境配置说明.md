# SynPharm 环境配置说明

本文档讲解 SynPharm 的**容器化环境配置**：目录结构、环境变量（`.env`）、一键启动、常用命令与排障。
Dockerfile 跟随各服务源码，编排与配置统一在 `deploy/` 目录管理。

## 目录结构

```
deploy/
├── docker-compose.yml     # 服务编排入口（MySQL + Redis + RabbitMQ + 后端 + FastAPI + 前端）
├── .env                   # 实际环境变量（由 start.bat 自动生成/修复，不进版本库）
├── .env.example           # 环境变量模板（仅供首次自动复制，不要覆盖已有的 .env）
├── scripts/
│   ├── start.bat / .sh    # 一键启动（Windows / Linux / macOS / WSL）
│   ├── stop.bat / .sh     # 一键停止
│   └── preflight.ps1      # 启动前端口检查（由 start.bat 自动调用）
└── 环境配置说明.md        # 本说明
```

## 快速开始（组员）

### 前置条件

- 安装 **Docker Desktop**（Windows）或 Docker Engine（Linux / macOS / WSL）
- **不需要手动启动 Docker Desktop** —— 未运行时脚本会自动拉起

### 第 1 步：启动

```bash
cd deploy

# Windows：直接双击，或在终端执行
scripts\start.bat

# Linux / macOS / WSL
chmod +x scripts/start.sh && ./scripts/start.sh
```

**就这些** —— 不需要手动复制 `.env`，也不需要手动改密码，脚本会自己处理。

### 第 2 步：验证访问

`start.bat` 跑完后，确认三个入口都能打开：

| 服务 | 地址 |
|---|---|
| 前端页面 | http://localhost （默认端口 80，可在 `.env` 改 `FRONTEND_PORT`） |
| SpringBoot 文档 | http://localhost:7000/doc.html |
| FastAPI 文档 | http://localhost:9050/docs |
| RabbitMQ 管理台 | http://localhost:15672 |
| 健康检查 | http://localhost:7000/actuator/health |

### `start.bat` 做了什么

| 步骤 | 行为 | 为什么需要 |
|---|---|---|
| `[1/6]` 定位 docker | `where docker` 找不到时，自动去 Docker Desktop 默认安装目录找，并并入本次会话 PATH | 终端若是在装 Docker **之前**打开的，PATH 里没有 `docker`，会被误报成"Docker 未运行" |
| `[2/6]` 确保引擎在跑 | 未运行则自动 `start` Docker Desktop，轮询 `docker info` 最多等 180 秒 | 省去手动点托盘图标再干等 |
| `[3/6]` 检查并修复 `.env` | 缺失则从模板创建；**为空或 `change-me*` 的必填凭据自动修复** | 见 [启动失败的三大真实原因](#启动失败的三大真实原因) |
| `[4/6]` 端口预检 | 检查 80 / 7000 / 9050 / 13307 / 6380 可绑定性，以及是否落在 Windows 保留段 | 避免构建十几分钟后才发现端口冲突 |
| `[5/6]` 校验配置 | `docker compose config --quiet` | 提前暴露 `.env` 语法问题 |
| `[6/6]` 启动 | 镜像已存在则**跳过构建**；不存在才 `--build` | 每次构建会在缓存被回收时重下 185 MB 的 torch，白等十几分钟 |

**第 3 步的修复规则**（避免误伤）：

- 只处理**空值**或**以 `change-me` 开头**的项，**你设过的密码一律不覆盖**
- 修复时优先从**已存在的容器**里读回真实值 —— 那才是与现有数据卷匹配的密码
- 仅当容器不存在（全新环境）时，才为 `JWT_SECRET` / `RABBITMQ_PASSWORD` 生成随机值

### 首次启动 vs 之后

| 场景 | 耗时 | 说明 |
|---|---|---|
| 首次（无镜像） | **10~30 分钟** | 拉基础镜像 + Maven 编译 + 装 torch（约 2~3 GB） |
| 之后（镜像已存在） | **十几秒** | 跳过构建，只 `up -d` |

> 所有服务都配了 `restart: unless-stopped`。首次启动成功之后，**只要 Docker Desktop 起来了，
> 6 个容器会自动全部恢复**，连 `start.bat` 都不用点。
> 建议在 Docker Desktop → Settings → General 勾选 *Start Docker Desktop when you sign in*。

### 改了代码要重新构建

```bash
scripts\start.bat rebuild      # 强制加 --build
```

### 环境变量详解

`.env` 中的全部可配置项（与 `deploy/.env.example` 一一对应）：

| 变量 | 默认值 | 说明 |
|---|---|---|
| `SYNPHARM_VERSION` | 1.0.0 | 镜像标签版本 |
| `MYSQL_ROOT_PASSWORD` | - | **必填**，MySQL root 密码 |
| `MYSQL_DATABASE` | synpharm | 数据库名 |
| `MYSQL_USER` | synpharm | 应用数据库账号 |
| `MYSQL_PASSWORD` | - | **必填**，应用账号密码 |
| `MYSQL_PORT` | 13307 | 宿主机 MySQL 端口（3307-3406 属 Windows/Hyper-V 保留段，不可用） |
| `REDIS_PORT` | 6380 | 宿主机 Redis 端口（避开 Windows 常见本地 Redis） |
| `REDIS_PASSWORD` | 空 | Redis 密码（生产建议设置） |
| `JWT_SECRET` | - | **必填**，JWT 签名密钥（≥32 字节） |
| `JWT_EXPIRATION` | 86400000 | Token 有效期（毫秒） |
| `FASTAPI_PORT` | 9050 | 宿主机 FastAPI 端口 |
| `FASTAPI_DEVICE` | cpu | 推理设备：cpu / cuda:0 |
| `FASTAPI_BATCH_SIZE` | 50 | 批量推理大小 |
| `FASTAPI_API_KEY` | 空 | 后端调用算法引擎的单一 Key（开启认证必填） |
| `FASTAPI_API_KEYS` | 空 | FastAPI 接受的全部 Key（逗号分隔，可多个） |
| `FASTAPI_LOG_LEVEL` | INFO | 日志级别 |
| `BACKEND_PORT` | 7000 | 宿主机后端端口 |
| `FRONTEND_PORT` | 80 | 宿主机前端端口 |
| `QQ_EMAIL` | 空 | 验证码发件邮箱 |
| `QQ_EMAIL_AUTH_CODE` | 空 | 邮箱授权码 |

> 修改 `.env` 后需重启服务生效：`scripts\start.bat`（或 `docker compose up -d`）
>
> ⚠️ **不要把 `.env.example` 复制覆盖到已有的 `.env` 上**。这是本环境最常见的故障来源：
> 数据卷里的密码是**首次初始化时**写死的，覆盖 `.env` 会让密码对不上，之后每次启动都会失败。
> 如果不小心覆盖了，`start.bat` 会自动从现存容器里把真值读回来。

## 常用命令

> 以下命令均在 `deploy` 目录下执行。

```bash
# 启动（镜像已存在时十几秒完成）
scripts\start.bat                 # Windows
./scripts/start.sh                # Linux / macOS / WSL

# 改了代码后强制重建镜像
scripts\start.bat rebuild

# 查看所有服务状态（含已停止的加 -a）
docker compose ps

# 查看日志（实时）
docker compose logs -f

# 查看某个服务日志
docker compose logs -f backend
docker compose logs -f fastapi

# 停止服务（保留数据）
scripts\stop.bat                  # 或 ./scripts/stop.sh

# 彻底清理（⚠️ 删除所有数据卷，数据库数据不可恢复）
docker compose down -v
```

## 启动失败的三大真实原因

> 以下三条均为实测踩过的坑。症状都是笼统的"启动失败"，但根因完全不同。

### 1. `.env` 被覆盖成模板（最常见）

**症状**

```
error while interpolating services.backend.environment.JWT_SECRET:
required variable JWT_SECRET is missing a value: 请在 .env 中设置 JWT_SECRET
```

或者：补上空值之后，MySQL 一直 unhealthy，`--wait` 最后超时报"启动失败"。

**原因**

`docker-compose.yml` 对 `JWT_SECRET` / `MYSQL_PASSWORD` / `MYSQL_ROOT_PASSWORD` /
`RABBITMQ_PASSWORD` 用了 `${VAR:?}` 语法 —— **为空时 compose 直接拒绝执行**。

更隐蔽的是**密码不一致**：MySQL 的账号密码是容器**首次初始化时**写进数据卷的，
之后再改 `.env` 不会同步过去。所以即使把空值补上，只要 `.env` 里的密码和卷里存的不是同一个，
MySQL 健康检查就会一直失败。

**处理**

`start.bat` 的 `[3/6]` 会自动修好。手工排查时，可以从现存容器里读回真值（**不需要删数据卷**）：

```bash
docker inspect synpharm-mysql    --format '{{json .Config.Env}}'
docker inspect synpharm-rabbitmq --format '{{json .Config.Env}}'   # 键名是 RABBITMQ_DEFAULT_PASS
docker inspect synpharm-backend  --format '{{json .Config.Env}}'
```

对照关系：

| `.env` 中的键 | 来源容器 | 容器内键名 |
|---|---|---|
| `MYSQL_ROOT_PASSWORD` / `MYSQL_PASSWORD` / `MYSQL_DATABASE` / `MYSQL_USER` | `synpharm-mysql` | 同名 |
| `RABBITMQ_USER` / `RABBITMQ_PASSWORD` | `synpharm-rabbitmq` | `RABBITMQ_DEFAULT_USER` / `RABBITMQ_DEFAULT_PASS` |
| `JWT_SECRET` | `synpharm-backend` | 同名 |

> 容器已被删、真值取不回来时，只能 `docker compose down -v` 清空数据卷重来 ——
> **数据库数据会全部丢失**，务必先确认。

### 2. 端口落在 Windows 保留段

**症状**

```
bind: An attempt was made to access a socket in a way forbidden by its access permissions
```

**原因**

Hyper-V / WSL 会保留成段的 TCP 端口，落在保留段内的端口无法绑定。
本机保留段包含 `3307-3406` 和 `8932-9031`，所以本项目默认用 `13307` 与 `9050` 绕开。

**排查**

```bash
netsh interface ipv4 show excludedportrange protocol=tcp

# 或直接跑启动前的检查脚本
powershell -NoProfile -File scripts\preflight.ps1 -Ports 80,7000,9050,13307,6380 -Names frontend,backend,fastapi,mysql,redis
```

**处理**：改 `.env` 里对应的 `*_PORT`。

### 3. 每次启动都重新构建镜像（看起来像卡死）

**症状**：`start.bat` 停在"构建并启动"十几分钟没有输出。

**原因**：Docker 的构建缓存会被回收（Docker Desktop 默认开启 builder GC）。
缓存没了之后，`pip install torch` 要重新下载约 185 MB，`apt-get update` 也要重跑。

**处理**：`start.bat` 现在**只在镜像不存在时才构建**，日常启动走快速路径。

## 其他常见问题

**Q：提示 `docker` 命令找不到，或报 "Docker 未运行" 但引擎明明在跑？**

终端是在装 Docker **之前**打开的，PATH 没刷新。三种解法：

- 新开一个终端（推荐）
- 或直接双击 `scripts\start.bat` —— 它会自己找到 `docker.exe`
- 或在当前终端手动补路径：

```powershell
$env:Path = "$env:LOCALAPPDATA\Programs\DockerDesktop\resources\bin;" + $env:Path
```

**Q：后端一直 unhealthy？**

```bash
docker compose logs backend
```

常见原因：数据库密码与数据卷不一致（见上文第 1 条）、`JWT_SECRET` 太短、Redis 连不上。

**Q：FastAPI 一直 unhealthy？**

```bash
docker compose logs fastapi
```

首次启动要安装 torch 依赖，耐心等待；也可确认 `synpharm-fastapi/models` 目录存在（可为空）。

**Q：前端页面打不开？**

确认 `FRONTEND_PORT` 未被占用，且后端已 healthy。

**Q：拉镜像超时 / `failed to fetch anonymous token`？**

Docker Hub 被墙。在本机 `%USERPROFILE%\.docker\daemon.json` 配置镜像加速源，然后重启 Docker Desktop：

```json
{
  "registry-mirrors": [
    "https://docker.m.daocloud.io",
    "https://docker.1ms.run",
    "https://docker.1panel.live"
  ]
}
```

验证：`docker info --format "{{json .RegistryConfig}}"` 能看到 Mirrors。

**Q：想保留数据、只把服务重启一遍？**

```bash
docker compose down        # 停容器，保留数据卷
scripts\start.bat          # 重新起
```

注意 `down -v` 会**连数据卷一起删**，数据库数据不可恢复。

## 新增 SQL 脚本必须手工执行一次（重要）

`docker-compose.yml` 把 `synpharm-backend/sql/` 挂给 MySQL 的 `/docker-entrypoint-initdb.d`，
而 **MySQL 只在数据卷为空时（首次初始化）才执行这个目录**。
已经跑起来的环境，**后加入的 `sql/*.sql` 不会自动生效**。

后果：表/列不存在，但代码已经在用 → 运行期才报错。真实踩到过的两个例子：

| 现象 | 缺失对象 |
|---|---|
| 批量上传直接 400「文件上传失败」，日志 `Table 'synpharm.batch_task_item' doesn't exist` | `sql/09_batch_task_item.sql` 未执行 |
| 登录/用户查询报 `Unknown column 'lab'` | `sql/09_sys_user_research_profile.sql` 未执行 |

**手工应用方式**（先 `docker cp` 进容器再重定向执行，避免在宿主机上被编码/引号问题干扰）：

```powershell
docker cp synpharm-backend\sql\09_batch_task_item.sql synpharm-mysql:/tmp/x.sql
docker exec synpharm-mysql sh -c 'MYSQL_PWD="$MYSQL_ROOT_PASSWORD" mysql -uroot < /tmp/x.sql'
```

**核对当前库里有哪些表**：

```powershell
"SHOW TABLES;" | docker exec -i synpharm-mysql sh -c 'MYSQL_PWD="$MYSQL_ROOT_PASSWORD" mysql -uroot -N synpharm'
```

> 注意：`09_sys_user_research_profile.sql` 用的是 `ALTER TABLE ... ADD COLUMN`，
> **不幂等**，重复执行会报 `Duplicate column name`。报这个错说明已经加过了，不是问题。

## 维护须知：`start.bat` / `stop.bat` 必须保持纯 ASCII

**不要在这两个脚本里写中文，注释也不行。** cmd.exe 解析含非 ASCII 字节的批处理文件时会错位，
把注释甚至 `echo` 当成命令去执行。实测结果：

| 文件编码 | 控制台代码页 | 结果 |
|---|---|---|
| UTF-8 | `chcp 65001` | ❌ 注释被当命令执行，连 `echo` 都被破坏 |
| UTF-8 | 不设 chcp | ❌ 同样出错 |
| GBK | 不设 chcp | ✅ 解析正常，但 UTF-8 终端里显示乱码 |

由于控制台代码页在不同环境不一致（VS Code 终端常是 65001，资源管理器双击是 936），
唯一稳妥的做法就是**只放 ASCII**；中文提示交给 PowerShell 输出（`Write-Host` 走控制台
Unicode API，任何代码页都显示正常）。

另外两点编写注意：

- `if (...)` 块内的 `echo` **不能出现裸括号**：`credential(s)` 里的 `)` 会被当成块结束符，
  报错形如「此时不应有 that。」→ 要写成 `credential^(s^)`
- 取路径要用 `%%~dpi`（变量字母在最后）。写成 `%%~dp` 只会得到盘符 `C:`

## 安全提醒

- `.env` 已加入 `.gitignore`，**不要提交到版本库**
- 生产环境务必：设置强密码/密钥、开启 FastAPI 的 `FASTAPI_API_KEYS`、限制数据库端口不对外暴露
- 本说明中的凭据读取命令（`docker inspect`）会打印**明文密码**，排查完注意清理终端记录
